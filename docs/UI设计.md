# EduHub UI 交互设计

| 项 | 内容 |
| --- | --- |
| 依据 | `docs/PRD.md` v1.8、`docs/架构设计.md` v1.6 |
| 版本 | v1.4 |
| 风格 | 简约学术：讲义 / 试卷，不是力扣深色竞赛风 |
| 范围 | 全站一套壳；桌面 + 手机浏览器 |

---

## 1. 背景与目标

站点给中小学生、教练、未登录家长看。首页是大纲和好处，进度公开。如果做成蓝按钮 SaaS 或力扣暗色，会像刷题站，不像教学材料。

- **目标**：打开即像一份印刷讲义；五个一级入口一眼能找到；做题页像拆开试卷（上试卷条，上题面下作答，输入即保存）。
- **非目标**：插画运营页、暗色主题（本期不做）、独立管理后台皮肤、动效展示。
- **否决**：Element Plus 默认亮蓝、大圆角卡片阴影、渐变 Hero、徽章游戏化、emoji、Inter/Roboto。

技术上仍可用 Element Plus 的表格和表单，但颜色、圆角、字体必须吃本文 token。

---

## 2. 视觉语言

### 2.1 从哪来

信奥现场材料：CCF 试卷（宋体题面、等宽样例框）、学校通知打印件、教学大纲的「一、二、三」。签名元素就是 **章节号 + 一条细横线**，不是大色块 Hero。

### 2.2 颜色

纸色偏冷灰（避开常见的奶油衬线 + 陶土橙模板）。强调色只用一处靛蓝，像学报封面，不用作大面积底。

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--paper` | `#F2F1EC` | 页底 |
| `--surface` | `#FFFEFA` | 内容区、表、编辑器外框 |
| `--ink` | `#1C1B17` | 标题、主按钮、正文 |
| `--muted` | `#6B6860` | 说明、次要信息 |
| `--rule` | `#D4D0C6` | 顶栏底线、表线、章节线 |
| `--indigo` | `#2F4A6A` | 链接、当前导航、题号 |
| `--ok` | `#2F5D3A` | 满分 / AC |
| `--mid` | `#8A5A12` | 部分分 |
| `--bad` | `#8B2E2A` | CE / 未通过；面积要小 |
| `--code-bg` | `#EBE8E0` | 样例、行内代码 |

主按钮：`--ink` 底、白字、圆角 2px。次按钮：透明 + `--rule` 描边。不要胶囊形大按钮。

状态不要只用颜色：满分写「100」、部分分写分数、未做写「—」，再辅以浅底标签。

### 2.3 字体

| 角色 | 字体 | 用法 |
| --- | --- | --- |
| 标题 | Noto Serif SC / Source Han Serif SC | 站名、首页 h1、章节名 |
| 正文 | Noto Sans SC | 导航、段落、表、表单 |
| 等宽 | IBM Plex Mono | 题号、代码、测试点、倒计时 |

标题字重 600，正文 400。正文行高 1.7。不要全站衬线（表和按钮用黑体）。

### 2.4 尺度

- 内容宽：阅读栏 40rem（首页三章）；题库/进度 72rem；做题页通栏，左右最多各留 24px。
- 页边：桌面左右 32px，手机 16px。
- 章节间距：首页章与章之间 64px，章内 24px。
- 圆角：控件 2px，不要 12px 卡片。
- 无投影。分割只用 1px `--rule`。

### 2.5 动效

只要按钮 `:active` 略压、链接下划线。尊重 `prefers-reduced-motion`。不做进场动画、数字滚动。

## 3. 全站壳

所有页同一套：顶栏 → 主列 → 页脚。教练 studio 也用这套，只是多几个链接。

```text
+--------------------------------------------------+
|  站名（衬线）    首页 题库 外部资料 榜单   登录 |
|  ------------------------------------------------|  ← 1px rule
|                                                  |
|                   主内容                           |
|                                                  |
|  ------------------------------------------------|
|  非 CCF 官方 · 仅供训练                            |
+--------------------------------------------------+
```

**顶栏**

- 左：站名「EduHub」，衬线，链到 `/`。不要 Logo 图。
- 中/右：五个字链。当前项 `--indigo` + 底边 1px，不要下划线动画。
- 最右：未登录「登录」；已登录显示用户名，点开：退出。教练另见「管理」。
- 窄屏：站名 + 「菜单」。菜单展开为全宽列表，五项 + 登录。

**页脚**（短）

一行：非中国计算机学会官方站点。训练与模拟用。GESP / NOI 报名请走官网。字号小，`--muted`。

**登录**

顶栏点「登录」出居中小面板（不是新站）：用户名、密码、登录。无公开注册；账号由教练在管理后台添加。

## 4. 各页

### 4.1 首页 `/`（公开）

纵向三章，不要卡片宫格、不要每日一题。

```text
EduHub
信息学奥林匹克训练

──── 一  学习信息学的好处
段落（后台文案）

──── 二  教学大纲
GESP 1–8     进入题单 →
CSP-J / S    进入题单 →
NOIP         进入题单 →
NOI          进入题单 →
每级下列知识点短句

──── 三  学习的时间节点
竖轴：月 | 事项 | 建议准备
例  3 / 6 / 9 / 12月  GESP
    9月               CSP 第一轮
    10–11月           CSP 第二轮
    11–12月           NOIP
```

章号用衬线小字「一」「二」「三」，右侧拉通 `--rule`。大纲行可点，进题库带筛选。时间轴桌面两列（日期 | 说明），手机单列。

### 4.2 题库 `/problems`

三层：题单 → 试卷列表 → 整卷竖排作答。中间不能省「选试卷」。

```text
左 12rem                右
全部                    [搜索试卷名]
GESP 1–8               --------------------------------
CSP-J                  试卷                         题数  进度    进入
CSP-S                  2023年9月 · C++ 1级          16   3/16    进入
NOIP                   2023年12月 · Python 2级     …
NOI
```

- 左栏题单；手机改横滑 chips。
- 右侧只列**试卷**（与竞赛列表同形），不直接铺全部小题。
- 点「进入」→ `/problems/papers/:contestId`：该卷全部题目**同一页纵向排列**（题面 + 作答），可滚动，自动保存。
- 整卷页左侧题号目录：未做灰框、已作答浅底、满分绿、部分分褐；**标记**后靛蓝描边。点题号跳转；每题可「标记 / 取消标记」（存本机）。
- 单题路由 `/problems/:id` 仍保留（管理预览、旧链接）。
- 教练另见：另有 N 道没有标准答案。

### 4.3 做题 `/problems/:id`

两种进法，**同一张做题页**，不要做成两个皮肤。

| 进法 | URL | 顶栏多什么 |
| --- | --- | --- |
| 题库单题 | `/problems/4244` | 无试卷条。若该题属于某套已发布卷，仍自动带上试卷条（与带 `contest` 相同）。 |
| 试卷内 | `/problems/4244?contest=159` | 必须有试卷条。 |

职责拆开：

- **试卷条**：换题、看进度。不放提交。
- **题面区**（上）：题干、样例、测试点分值。
- **作答区**（下）：选项或编辑器。输入即写入结果，无提交按钮。

#### 4.3.1 布局

宽屏和窄屏同一结构：上题面、下作答。不要左右分栏。

```text
全站顶栏（首页 题库 竞赛 …）
----------------------------------------------------------------
试卷名（链回 /contests/159）     3 / 16     已保存…
[1] [2] [3] [4] … [16]                    [上一题] [下一题]
题号：当前靛蓝框；满分绿色；已做褐色；有作答浅底。
GESP-…-C03   循环结构
1000 ms · 128 MB · 标准输入输出          ← 仅编程题
----------------------------------------------------------------
题面
样例 / 测试点分值表
----------------------------------------------------------------
作答
  选择：单选列表
  或 语言 + 编辑器  [运行样例]
  已保存 / 评测中 / 测试点表
```

- 试卷名用正文。点试卷名回竞赛页。
- 题号签：等宽数字、1px `--rule` 方框、最小 36×36（窄屏 44×44）。当前题 `--indigo` 边。不要圆点、不要徽章。
- 状态不只靠颜色：悬停写「未做 / 已作答 / 70 分 / 100 分满分」。页下用一句图例。
- 上一题 / 下一题只出现在试卷条右侧。第一题上一题禁用，最后一题下一题禁用。
- 题面与作答用一条 `--rule` 横线分开，作答在题面正下方。
- 选择题：每一行是「圆点 + 题号 + 正文」，同一基线对齐；圆点不要单独占一行。选项里的代码与题面相同处理。
- 题面用 Markdown 渲染（`marked`）：标题、段落、围栏代码块。代码块用 `highlight.js` 高亮 C++ / Python，底色 `--code-bg`、等宽 IBM Plex Mono、圆角 0。不要用 Monaco 只读窗当题面。不要上 Element Plus 单选。
- **没有「提交」「保存进度」**。编程题可有次按钮「运行样例」（非正式分）。没有样例时禁用，不要藏掉。
- 缺标准答案：作答仍保存。一句：「本题还没有标准答案。作答会记下，但不评分。」
- 最后一题作答区可有「本卷最后一题，返回试卷」。不要自动跳下一题。

#### 4.3.2 交互

**进页**

1. 未登录可看题面、可在本机作答。成绩记到账号需登录；不要一输入就弹出登录。
2. 带 `contest` 时，作答记在该卷上；无参数但能匹配到唯一所属卷，行为相同。
3. 换题先写入当前作答，再打开下一题。不要整页白闪：题面和作答一起换。

**实时保存（即结果）**

- 点选项、改代码后约 1 秒写入。登录账号存服务端并记为该题结果；未登录只存本机，文案「已保存在本机。登录后成绩才会记到账号上。」
- 选择题：选中即是答案，有标准答案则当场评分，题号签变色。
- 编程题：代码即是作答；停笔后自动评测（练习 / IOI 出分；OI 赛中只显示已记下）。换题或离开页面也会写入并评测。
- 再进 `/contests/159`：有进度则「继续做题」，否则「开始做题」。列表成绩：未做 / 草稿 / 分数。

**评测反馈（无提交按钮）**

1. 自动评测时作答区写「评测中」或「排队中」。单机串行必须让人看见。
2. 练习 / IOI：出分。结果用字：通过、答案错误、超时、运行错误、编译失败、部分分，后面跟分数。测试点表：点号、结果、分。AC 用 `--ok` 字色。
3. 「运行样例」结果上方固定一句：非正式分。仅跑了公开样例。点运行样例时未登录 → 登录面板。
4. OI 赛中：只显示「已记下」，不渲染测试点、不显示分数。
5. 无标准答案：状态「已记下，不评分」，不要判成 WA。

**选择题 vs 编程题**

同一作答区骨架，只换控件。选择题没有「运行样例」。不要两套页面。

#### 4.3.3 窄屏

仍是题面在上、作答在下。试卷条题号可换行。上一题/下一题热区 ≥ 44px。

#### 4.3.4 否决（本页）

- 左右分栏（左题面右编辑器）。
- 「提交」「保存进度」按钮。
- 必须点提交才记分。
- 题号只用颜色、不写分数含义。
- 自动跳下一题。
- 力扣式底部讨论、大圆角状态胶囊、暗色编辑器。

### 4.4 竞赛页（已移除）

学生侧不再提供 `/contests` 列表。试卷从题库进入：`/problems` → `/problems/papers/:id`。旧链接 `/contests`、`/contests/:id` 分别重定向到题库与整卷页。教练仍可在管理里发布试卷。

### 4.5 外部资料 `/external`

学年时间轴 + 右侧说明。每条：赛事名、日期、对象、链到官网、已上架真题则「看题」。按钮文案「前往 NOI 官网」，不要「立即报名」（本站不代报）。

### 4.6 榜单 `/progress`（公开，手机优先）

家长未登录就看这一页。

```text
学生     题库（满分/部分/未做）   最近比赛     最近提交
张三     12 / 5 / 40            J2模拟 280   2小时前
```

- 桌面表；手机每人一块：名字、三枚分数、最近比赛。
- 点名字进 `/progress/:id`：只显示各题最高分和比赛得分，**无代码、无测试数据**。
- 默认按最近提交排。不要公开排行榜奖杯。

### 4.7 管理 `/studio`（教练）

同一顶栏，主列内二级：**题目、首页文案、比赛、账号**。不要深色 Admin 模板。表单左对齐、标签在上。

**题目**（一张表管试卷，一张表管单题）

```text
试卷
[全部] [未发布] [已发布]   搜索试卷名
试卷名              种类   题数  有答案  状态     动作
GESP 2023年9月…     真题   3     3      已发布   撤回

点试卷名展开：
题号              标题        类型   答案              动作
GESP-…-C01       循环结构     选择   有                编辑
```

全部题目表同样有「编辑」→ `/studio/problems/:id`。

**编辑页** `/studio/problems/:id`

- 可改：题号、标题、来源、难度、类型、语言、时限内存、满分、发布、备注、题面、样例、选择题选项与答案、测试点。
- 题面旁预览（`StatementView`）。
- **保存**：写 SQLite（本机立刻生效）+ 写 `data/catalog/problems/{题号}.json`。
- 成功提示：上线请 git commit/push 后服务器 deploy（deploy 会跑 `apply-catalog.mjs`）。

- 种类只有标注：真题 / 练习。布局必须相同。
- 学生题库只显示有标准答案的已发布题。管理表能看到无答案题，筛选项：全部 / 有答案 / 无答案。
- 撤回要确认：「学生将看不到这套试卷和卷内题目。」

**首页文案**：三块大文本框（好处、大纲 JSON、时间节点 JSON）。

**比赛**：创建模拟赛（名称、赛制、时长、起止、题目 id）。

**账号**：只读表。

## 5. 组件约定

| 组件 | 做法 |
| --- | --- |
| 筛选 | 文字 + 下划线选择，不要一排实心 chip |
| 标签（来源/难度） | 小字 + `--code-bg`，圆角 2px |
| 测试点矩阵 | 等宽表：点号、结果、分；AC 用 `--ok` 字色 |
| 空态 | 「本题单暂无题目。」一句，不要插画 |
| 加载 | 表区写「载入中」，不要全屏骨架屏闪烁 |
| 错误 | 一句人话 + 可再试；评测失败写 CE/TLE 等缩写并附一行解释 |
| 排队 | 「前方还有 N 份评测」（单机串行，必须让人看见） |

文案用完整中文。按钮：「运行样例」「上一题」「下一题」「开始做题」「继续做题」「进入」。不要「提交」「保存进度」「Submit」「Go」。竞赛列表不要「报名」；登录后在详情里自动报名。

## 6. 适配

断点：`<768px` 窄，`≥768px` 宽。

| 页 | 窄屏 |
| --- | --- |
| 壳 | 汉堡菜单 |
| 首页 | 三章单列，时间轴竖排 |
| 题库 | chips + 卡片 |
| 做题 | 上题面下作答；输入即保存 |
| 榜单 | 卡片，可点进详情 |
| 竞赛/外部 | 一行变块，日期在标题下 |
| 管理 | 能看列表；改题面以电脑为准 |

触控热区 ≥ 44px。题面图片 `max-width:100%`。

## 7. 无障碍与合规露出

- 对比：正文与纸色 ≥ 4.5:1。链接不只靠蓝，带下划线（正文内）。
- 焦点：键盘可见 2px `--ink` 框。
- 顶栏当前项用文字样式，不只靠颜色。
- 非官方声明在页脚，首页时间轴附近再出现一次短句即可，不要水印盖正文。

---

## 8. 实现（给前端）

- 全局 CSS 变量写在一处。Element Plus 若用表格，颜色必须吃 token；选择题不要用它的 Radio。
- 题面：`marked` + `highlight.js`（C++ / Python），代码块 `--code-bg`。Monaco 只用于作答编辑器，不当只读题面。
- 不要引入第二套 UI 库。
- 站名、导航、页脚抽 `AppShell`。

---

## 9. 验收

- 首页三章、无每日一题、无大 Banner。
- 榜单未登录可打开，无源码。
- 做题页上题面下作答；无提交按钮；输入即保存。
- 试卷内做题：试卷条负责换题；换题不整页空白。
- 竞赛列表只「进入」详情；详情里「开始做题 / 继续做题」。
- 管理试卷一张表，真题/练习布局相同。
- 主色不是 Element 默认蓝；无大阴影圆角卡片。
- 页脚有非官方说明。
