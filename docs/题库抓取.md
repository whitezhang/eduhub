# 题库抓取

解析结果进 `src/rd/server/data/seed/`，部署时导入 SQLite。原版 PDF 只在 `cache/`，不进 git。

## GESP

GESP **客观题（选择 / 判断）双源抓取、按题号合并**；**编程题**仅 CCF 官方 PDF 有完整题面与参考程序，AdaCpp 不提供。

### 已知缺陷（决定合并分工）

| 来源 | 主要问题 | 仍可靠的部分 |
| --- | --- | --- |
| **CCF 试题 PDF** | PyMuPDF 按块排序后，题面/选项可能出现**文本错序、页码碎片、行号列、代码块串入相邻题**（尤其含大段代码的选择题） | 卷面**完整**；**节首答案表**（见下）；**编程题**题面、样例、`参考程序` |
| **CCF 解析 PDF** | 逐题解析正文同样可能有排版噪声 | 逐题文字解析；部分卷另有答案表，与试题卷重复时可作校验 |
| **AdaCpp** | **无编程题**；部分 `gesp-*` 套卷 API 返回空或未上架（如部分 `6ji-202512`）；Python 套卷常缺失 | 网页 HTML **题面/选项较干净**；有卷时选择/判断**答案覆盖率高** |

结论：**不能**把「PDF 题面优先」当作全局规则；两源应**按字段互补**，而非一方覆盖另一方。

### 合并主键

同一道题在三个来源间用 **题号** 对齐，与库内 `code` 一致：

```text
GESP-{ym}-{CPP|PY}{level}-{C|J}{seq:02d}
例：GESP-202512-CPP6-J03
```

套卷对齐键：`(ym, lang, level)`。AdaCpp 的 `gesp-cpp-6ji-202512` 与 PDF `202512-cpp-6` 视为同一套。

### PDF 试题：客观题答案版式

**答案不在卷末**，而在每一类题目的**章节标题正下方**，紧接「第 1 题」之前。

```text
1 单选题（每题 2 分，共 30 分）
┌──────┬───┬───┬───┬ … ─┐
│ 题号 │ 1 │ 2 │ 3 │     │   ← 15 列（选择）或 10 列（判断）
│ 答案 │ C │ C │ C │ …   │   ← 选择：A–D；判断：√ / ×（或 对/错）
└──────┴───┴───┴───┴ … ─┘
第 1 题 …

2 判断题（每题 2 分，共 20 分）
┌──────┬───┬ … ─┐
│ 题号 │ 1 │     │   ← 10 列
│ 答案 │ × │ √ │ … │   ← √ → T，× → F
└──────┴───┴ … ─┘
第 1 题 …
```

解析要点：

- **按节提取**：在 `单选题` / `判断题` 分段内，先解析节首 `题号`+`答案` 两行表，再解析下方各 `第 N 题` 题干。
- **勿**只在全文末尾找答案表；也**勿**假设答案仅在「解析 PDF」里。
- 判断题答案可能是 Unicode `√` `×` 或 PDF 抽取后的等价字符，需归一化为 `T` / `F`（或 `对` / `错`）。
- **实现注意**：部分试卷判断题答案为 PDF **矢量图形**（非文字），`pymupdf` 文本抽取拿不到 √/×。
- **本机导入**：`gesp_tf_vision.py` 对节首答案表截图，用视觉模型识别（或矢量符号回退），写入 `seed/gesp/`；**线上 deploy 不装此依赖**。

### 判断题答案：本机视觉识别（仅导入）

判断题 √/× 常为 PDF 矢量图，需在本机解析阶段处理：

```bash
pip install -r src/op/requirements-gesp-vision.txt   # 可选：openai
# 方式 A：OpenAI 视觉（推荐，模型好）
set OPENAI_API_KEY=sk-...
set GESP_TF_VISION_MODEL=gpt-4o

# 方式 B：本地 Ollama
ollama pull llava:13b
set GESP_TF_VISION_PROVIDER=ollama
set GESP_TF_VISION_MODEL=llava:13b

# 重解析 PDF（默认先尝试矢量符号匹配，失败再走视觉）
python src/op/gesp_import.py --skip-crawl --reparse --no-import

# 强制全程用视觉模型
python src/op/gesp_import.py --skip-crawl --reparse --no-import --tf-vision
```

| 环境变量 | 说明 |
| --- | --- |
| `OPENAI_API_KEY` | 设置后 `auto` 模式优先用 OpenAI 视觉 |
| `GESP_TF_VISION_PROVIDER` | `auto` / `openai` / `ollama` |
| `GESP_TF_VISION_MODEL` | 默认 `gpt-4o` 或 `llava:13b` |
| `GESP_TF_VISION=1` | 等同 `--tf-vision` |

未配置视觉 API 时，脚本用 PDF 矢量路径启发式（27/30 笔画）识别 √/×；多数 CCF 卷可零成本跑通。

- 解析 PDF 仍可作为**逐题解析正文**来源；其答案表若与试题节首表不一致，以**试题 PDF 节首表**为准。

当前 `gesp_import.py` 的 `parse_answer_rows()` 按全文匹配 `题号…答案`，在块排序异常时易漏抓（现有 seed 客观题 `answer` 全空即与此有关）；实现合并时应改为**节内**解析（待改）。

### 字段合并规则

合并产物写入 `seed/gesp-merged/`（**进 git，导入读此目录**）。

#### 总原则

```text
题面/选项：AdaCpp 有则用 AdaCpp → 否则用「质量过关」的 PDF 试题 → 否则保留较差一方并标记
答案：     PDF 试题（节首答案表）→ PDF 解析卷 → AdaCpp → 仍空则标记缺答案
编程题：   仅 PDF 试题（AdaCpp 不参与）
```

#### 分字段

| 字段 | 优先 | 回退 | 说明 |
| --- | --- | --- | --- |
| **题面 `statement`** | AdaCpp（该套卷存在且本题有内容） | PDF 试题（通过质量检测） | PDF 块排序易脏；AdaCpp HTML 通常更干净 |
| **选项 `options`** | 同上 | 同上 | 与题面同源，不混用两源的选项 |
| **答案 `answer`** | PDF **试题**节首答案表 | PDF 解析卷 → AdaCpp | 官方试题卷内表；结构简单、误解析概率低于题干正文 |
| **解析 `explanation`** | CCF 解析 PDF（可拆时） | AdaCpp | 可拼接，PDF 段标注「官方解析」 |
| **`review_note`** | — | — | `sources`、缺答案、冲突、PDF 低质量兜底等 |

#### PDF 题面质量检测（未过检则不用作题面/选项）

合并时对 PDF 试题 stem 打标，**任一命中即视为低质量**，题面/选项改走 AdaCpp 或标记 `pdf_stem:low`：

- 含页眉页脚碎片：`第\s*\d+\s*页\s*/\s*共`
- 连续孤立行号列：多行仅 `\d{1,2}`（PDF 行号误入正文）
- 选项区异常：某选项文本过长（如 &gt; 500 字）或 A–D 不全
- 与 AdaCpp 同源题**字符相似度极低**且 PDF 侧命中上述噪声（可选对照）

低质量 PDF 题面**仍保留在 `seed/gesp/` 供人工对照**，但不写入合并结果的 `statement`。

#### 答案冲突

PDF 试题节首表、解析 PDF、AdaCpp 中**任意两方均非空且不一致**时：

1. **采用 PDF 试题节首答案表**
2. `review_note` 追加：`答案冲突：试题PDF=X 其他=Y`
3. 导入日志汇总题号

#### 缺卷 / 缺答案

| 情况 | 处理 |
| --- | --- |
| AdaCpp **整卷缺失** | 题面/选项用 PDF 试题（过检则用）；**答案用试题 PDF 节首表** |
| AdaCpp 有卷但**部分题无答案** | 题面仍用 AdaCpp；用 **试题 PDF 节首表** 补 `answer`（不必等解析卷） |
| 合并后答案仍空 | 题面照常展示，**不自动评分**；`review_note`：`标记：缺答案` |

#### Python 卷

- AdaCpp 常无 `gesp-python-*`：**题面/选项**来自 Python 试题 PDF（同样走质量检测）
- **答案**：优先 Python **试题 PDF** 节首表；仍空则镜像同 `(ym, level)` 的 C++ 合并结果

### 编程题（不合并）

| 字段 | 来源 |
| --- | --- |
| 题面、样例、测例 | CCF **试题** PDF |
| `solution_code` | CCF **试题** PDF「参考程序」段 |

AdaCpp 不参与编程题。

### 流水线

```text
1. 试题 PDF  → parse → seed/gesp/           （题面 + 节首答案表 + 编程）
2. 解析 PDF  → parse → 并入 seed/gesp/      （逐题解析 explanation；答案仅作校验/补洞）
3. AdaCpp    → scrape → seed/gesp-adacpp/
4. 合并       → gesp_merge_objective.py → seed/gesp-merged/   （或 import 时现场合并）
5. 导入 DB   → gesp_objective_import.py   （客观题，来自合并结果）
              → gesp_import.py --prog-only （仅编程题 + 套卷挂接）
```

线上 `deploy-server.sh` 顺序与上相同（均 `--skip-crawl`，只用 seed）。

## 「有答案」判定标准

站点与管理端里的「有答案 / 无答案」，指**能否按标准自动判分**，不是泛指「题面是否完整」。

| 题型 | 算「有答案」 | 数据库字段 | 数据来源 |
| --- | --- | --- | --- |
| **选择 / 判断** | 标准选项键非空（如 `A`、`T`） | `choice_json.answer` | 合并后：试题 PDF 节首表 &gt; 解析 PDF &gt; AdaCpp |
| **编程** | **满分参考程序非空** | `solution_code` | CCF 试题 PDF「参考程序」 |

**不算有答案的情况（编程题）：**

- 只有样例输入/输出（`sample_in` / `sample_out`）
- 只有测例文件（`testcases`）
- PDF 未解析出「参考程序」段

**产品行为：**

- **有答案**：客观题可判对错；编程题具备参考程序（样例测例仍可用于提交评测，但「无答案」标记看的是 `solution_code`）。
- **无答案**：学生可见、可作答，**不自动评分**；教练端显示「无答案」标记。
- **补全**：管理端 Studio → 编辑题目 → 客观题填标准答案，编程题填「满分程序」。

实现见 `src/rd/server/api.mjs` 中 `hasAnswerSql()` / `problemHasAnswer()`。

## 合并效果预期

| 场景 | 合并后 |
| --- | --- |
| AdaCpp 有卷、题面正常 | **题面/选项用 AdaCpp**；**答案优先试题 PDF 节首表**，AdaCpp 补空 |
| AdaCpp 有卷、仅判断缺答案 | 题面仍用 AdaCpp；**试题 PDF 判断节首表**补 J 题 |
| AdaCpp **整卷缺失** | 题面用 PDF 试题（质量检测）；**答案用试题 PDF 节首表** |
| 仅 AdaCpp、本地无 PDF | 题面与答案均用 AdaCpp；`sources: adacpp` |
| PDF 与 AdaCpp 答案不一致 | 采用 **PDF 解析**答案，并记冲突 |
| 编程题 | **始终仅 PDF 试题**；与客观题合并进同一套卷 |

## 方案是否合适（小结）

| 诉求 | 做法 |
| --- | --- |
| PDF 题面易脏 | **不以 PDF 题面为默认优先**；AdaCpp 有卷时用 AdaCpp，PDF 作缺卷兜底 + 质量门控 |
| AdaCpp 无编程 | 编程题链路不变，仅 `gesp_import.py` 写 PDF |
| AdaCpp 缺年/缺卷 | PDF 试题 + 解析卷保证**场次齐全**与**答案可补** |
| 答案权威性 | **试题 PDF 节首答案表**优先；解析 PDF / AdaCpp 补洞 |
| 长期 | 合并脚本产出 `gesp-merged`；PDF 解析器持续加清洗规则，低质量卷进 Studio 人工列表 |
