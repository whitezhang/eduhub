## 背景

### 业务目标

EduHub 是信奥训练站：题库、整卷练习、串行评测、公开进度榜。用户量预期为**小规模班级训练**，不是公网高并发 OJ。

### 运行环境与约束

| 项 | 值 |
| --- | --- |
| 机器 | **2 核 CPU、2 GB 内存**（2G2C） |
| 系统 | Linux 生产 + Windows 本地开发 |
| 网络 | Nginx 对外 80/443；API 仅本机 `127.0.0.1:8081` |
| 编译器 | 本机 `g++`、`python3`（学生代码评测） |

### 内存预算（约）

| 占用 | 估计 |
| --- | --- |
| 系统 + Nginx | 400–600 MB |
| Node API + SQLite | 100–150 MB |
| 一次 g++ / 学生进程 | 200–400 MB |
| 余量 | 必须保留，否则 OOM |

### 设计边界（由 2G2C 决定）

- 单机单进程，不跑 Docker / PostgreSQL / Redis / 独立评测机。
- 评测全局串行（同时只跑 1 份学生程序）。
- 数据与代码同在仓库目录内，测试/生产分库。
- 能少一个常驻进程就少一个。

## 整体设计

### 服务形态

采用 **CS（Client-Server）架构**：浏览器 SPA（`src/rd/client`）经 HTTP 调 Node API（`src/rd/server`），同域 Cookie 会话。Nginx 分发静态资源和 `/api/*`。

```text
浏览器
  ├─ 静态资源（Vite 构建）──► Nginx 站点根
  └─ /api/* ──► Nginx 反代 ──► 127.0.0.1:8081  eduhub-api（单 Node 进程）
                                    │
                    SQLite + data/  ◄┤ 账号、题目、提交、CMS、政策
                    进程内评测队列  ◄┤ spawn g++/python，同时仅 1 份
```

### 关键决策

| 议题 | 选用 | 不选 | 原因 |
| --- | --- | --- | --- |
| 拓扑 | Nginx + 单 API 进程 | 独立 Judge 进程 | 2G 余量不足 |
| 数据库 | SQLite | PostgreSQL / Redis | 无额外服务、备份即拷文件 |
| API 运行时 | Node ≥22 ESM | Go 单体 / Express | 与前端同生态；路由量小 |
| 评测并发 | 进程内串行队列 | 并行 N 路 | 内存可预测，防 OOM |
| 结果推送 | 客户端轮询 1–2s | WebSocket | 轮询够用，少一种长连接 |
| 前端 | Vue 3 + Vite + Monaco | 静态站点生成 | 做题页需编辑器交互 |
| 鉴权 | 同域 Cookie 会话 | JWT | 无跨域多端需求 |
| 数据目录 | 仓库内 `data/`，按环境分库 | 系统目录 `/var/...` | 路径固定、易备份 |

### 本期不上

Docker、PostgreSQL、Redis、独立评测机、WebSocket、微服务、桌面客户端。

## 详细设计

### 技术选型

| 层 | 选型 |
| --- | --- |
| 网关 | Nginx（静态 + `/api/` 反代） |
| Client | Vue 3、Vite、Element Plus、Monaco |
| Server | Node ≥22、ESM、`node:http`、单进程 `index.mjs` |
| 数据库 | SQLite（`node:sqlite`） |
| 鉴权 | Cookie 会话 + bcrypt |
| 评测 | `child_process.spawn`；g++ / python3；串行队列 |
| 政策抓取 | `policy-sync.mjs`；定时仅生产 |
| 公开赛抓取 | `contest-sync.mjs`；定时仅生产 |
| 配置 | `src/op/conf/test.json` / `prod.json`，`EDUHUB_ENV` |
| 部署 | `git pull` + `npm ci` + `systemctl restart eduhub-api` |

### 仓库目录

```text
eduhub/
  docs/                         产品 PRD、架构/设计文档
  src/
    rd/
      client/                   Vue SPA
      server/                   API 入口 index.mjs
        paths.mjs               数据路径（限定在仓库内）
        policy-sync.mjs         国家政策抓取
        contest-sync.mjs        公开赛/活动抓取
        data/                   数据根（始终在仓库内）
          seed/                 种子 JSON、cms.json（进 git）
          catalog/problems/     教练改题 JSON（进 git）
          runtime/
            test/eduhub.db      测试库（gitignore）
            prod/eduhub.db      生产库（gitignore）
          cache/{env}/          抓取缓存（gitignore）
    op/                         部署脚本、导入、policy/contest-sync CLI
      conf/test.json | prod.json
      eduhub_paths.py
    qa/                         测试脚本
```

题库抓取流程见 `题库抓取.md`。

### Server 模块

| 模块 | 职责 |
| --- | --- |
| auth / user | 登录、学生/教练 |
| cms | 首页 STAR、新闻导语；`GET /api/cms?scope=home\|policy\|contests` |
| policy-sync | 抓取政策 → `policy_items` |
| contest-sync | 抓取公开赛 → `contest_items` |
| problem | 题库、题单、题面 |
| submit | 提交、样例、历史 |
| judge | 内存队列 + 串行 spawn |
| contest | 练习卷 / OI / IOI |
| external | 官方赛历 |
| progress | 公开进度（无源码） |

### 路由

`/`、`/news/policy`、`/news/contests`（`/policy` 重定向）、`/syllabus`、`/problems`、`/problems/papers/:id`、`/external`、`/progress`、`/studio`。旧 `/contests` → 题库。

### 提交流程

```text
POST /api/submissions → SQLite status=queued → 进程内队列 → 编译 → 跑测例 → 写回
Client 轮询 GET /api/submissions/:id（1–2s）
```

硬性约束：

- 全局互斥：同时 0 或 1 个学生程序在跑。
- `spawn` 必须超时；超时杀进程树。
- 学生程序内存上限 ≤ 128 MB。
- 测例目录：`data/runtime/{env}/problems/{id}/`。
- 生产不以 root 运行 Node。

### 数据

**路径规则**：

- 数据根：`src/rd/server/data`。
- `DATA_DIR` / `EDUHUB_DB` 若设置，也必须在仓库根目录内。
- `EDUHUB_ENV=test|prod` 决定库文件路径。
- 旧路径 `data/runtime/eduhub.db` 首次启动迁到 `runtime/test/`。

**主要表**：`users`、`cms_blocks`、`problems`、`testcases`、`submissions`、`contests`、`contest_problems`、`contest_registrations`、`external_events`、`guest_usage`、`policy_items`、`contest_items`。

**新闻同步**：`policy-sync.mjs` / `contest-sync.mjs`；手动 `npm run policy-sync` / `npm run contest-sync`；生产每日 06:00 / 06:30；新条目默认 `pending`，Studio 审核发布。

### 环境配置

`src/op/conf/` 区分测试（`test.json`）与生产（`prod.json`）；`EDUHUB_ENV` 选择环境。本地 `npm run dev` 默认 test，API `:8081`。

### 部署

**生产（Linux）**

| 项 | 值 |
| --- | --- |
| 工作树 | `/root/deploy/eduhub` |
| 站点根 | `/www/wwwroot/edu.jsoner.cn` |
| API 端口 | `8081` |
| systemd | `EDUHUB_ENV=prod`、`PORT=8081` |

| 脚本 | 作用 |
| --- | --- |
| `deploy.sh` | `git fetch` + `reset --hard`；**禁止 git clean**（保留 SQLite） |
| `deploy-client.sh` | `output/` → Nginx 站点根 |
| `deploy-server.sh` | `npm ci`、`apply-catalog.mjs`、重启 API、健康检查 |
| `apply-catalog.mjs` | `catalog/problems/*.json` upsert 进库 |

**改题上线**：Studio 编辑 → 写入 `catalog/problems/{题号}.json` → git push → 服务器 `deploy.sh`。

Nginx：`location /api/` → `127.0.0.1:8081`；SPA `try_files ... /index.html`。

**本地（Windows）**：Node ≥22、MinGW（g++）、Python 3 → `npm run dev`。

## 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| OOM（2G 内存） | 评测或编译时进程被杀 | 串行评测；学生程序内存上限 128MB；保留系统余量 |
| 评测阻塞 | 多人同时提交时排队久 | 前端显示「前方还有 N 份」；班级规模小可接受 |
| SQLite 并发写 | 高峰写入冲突 | 单进程 + WAL 模式；规模小可接受 |
| 单点故障 | 机器宕机全站不可用 | 定期备份 `eduhub.db` 和 `data/`；班级规模可接受 |
| 磁盘满 | 测例/日志占满 | 定期清理 `tmp/`；监控磁盘 |
| 配置误用 | test/prod 库混用 | `EDUHUB_ENV` 强制分库；部署脚本写死 prod |
| 安全暴露 | 匿名接口被爬 | `guard.mjs` Challenge + 限速；受保护 API 401 |
| 新闻抓取失败 | 新闻页数据过期 | 保留上次缓存 + `synced_at` 提示 |
