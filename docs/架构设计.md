# EduHub Web 架构设计

| 项 | 内容 |
| --- | --- |
| 依据 | `docs/PRD.md` v1.8 |
| 版本 | v1.6 |
| 形态 | 网站；C/S = 浏览器 SPA + 本机 Node API |
| 约束 | 腾讯云 **单机 2 核 2G**；部署对齐 `D:\workspace\codes\blog` |
| 原则 | 能少一个进程就少一个；后端用 **JavaScript（Node）**，与 blog 同一运行时 |

对照结论：拓扑仍是 **Nginx 静态 + 一个 API 进程**。后端由 Go 改为 Node，与 blog 的 `jsoner-api` 同栈；评测仍串行，学生程序是 g++/python 子进程，不是在 V8 里跑 C++。

---

## 1. 结论：和 blog 一样简单

blog 现网：

- Nginx 托管静态
- `/api/` 反代 `127.0.0.1:8080`（`jsoner-api`）
- systemd **一个** Node 服务
- **SQLite**（`node:sqlite`）+ 仓内目录，gitignore；不用 Docker、不用独立数据库机

EduHub 同一套拓扑，但和 blog **同机**：对外仍是 Nginx 80/443，按 Host 分流；本机 API 端口必须错开（blog `8080`，EduHub `8081`）。Client 用 Vue（做题页需要 SPA，不能用 Hugo）。Server 用 **一个 Node 进程**：HTTP API + 串行评测调度。

```text
浏览器
  ├─ HTML/CSS/JS  ──► Nginx 站点根（Vite 产物，edu.jsoner.cn）
  └─ /api/*       ──► Nginx ──► 127.0.0.1:8081  eduhub-api (Node)
                                              │
                         SQLite + data/  ◄────┤ 账号、题目、提交、测例文件
                         串行 spawn g++/python  ◄── 同时只跑 1 份学生程序
```

本期 **不上**：Docker、PostgreSQL、Redis、MinIO、独立 Judge 机、WebSocket、K8s、微服务、Go。

---

## 2. 2C 2G 为什么仍要简单

| 占用 | 约 |
| --- | --- |
| 系统 + Nginx | 400–600 MB |
| Node API + SQLite | 100–150 MB（比 Go 高一截，2G 仍放得下） |
| 一次 g++ / 学生进程 | 预留 200–400 MB |
| 余量 | 必须留着，否则 OOM |

- 评测 **串行**，禁止并行编译。
- 学生程序内存上限建议 ≤ 128 MB。
- 不用 PG/Redis。
- 提交结果 **轮询** `GET /api/submissions/:id`。

## 3. 技术选型

| 层 | 选型 | 相对 blog |
| --- | --- | --- |
| 对外 | Nginx | 相同 |
| Client | Vue 3 + TS + Vite + Element Plus + Monaco | blog 是 Hugo |
| Server | **一个 Node 进程**（Node ≥ 22，ESM，`node:http`） | 与 `jsoner-api` 同运行时 |
| 数据 | SQLite：`node:sqlite`（与 blog 相同，不另装 better-sqlite3） | 相同 |
| 鉴权 | 同域 Cookie 会话 | 相同 |
| 评测 | `child_process` 调本机 g++ / python3，进程内队列串行 | blog 无此项 |
| 部署 | `src/op/deploy.sh`：`npm ci` + `systemctl restart` | 抄 blog |
| 本地 | Windows：Nginx + `node src/rd/server/index.mjs` | 对应 blog 本机预览 |
| 线上 | 腾讯云 Linux 单机 | 同一类机器 |

不选：桌面客户端、独立 App、Docker、PG/Redis、Java、Go、Express（blog 已否决另起 Express，EduHub 同样用 `node:http` 分发，路由拆模块即可）。

## 4. JS 和 Go 在本项目里差在哪

学生代码 **从来不是** 用 Go 或 Node 解释执行，两种语言都是：API 收代码 → 写临时文件 → **spawn 系统编译器** → 读输出。差的是「管家」语言，不是评测语义。

| 维度 | Node（本期） | Go（旧方案） |
| --- | --- | --- |
| 和 blog 运维 | **同一套**：Node、npm、systemd、`node:sqlite` | 线上要多装 Go 工具链，部署脚本分叉 |
| 二进制 | 解释运行，依赖本机 `node` | 单文件、可交叉编译 |
| 常驻内存 | 更高（约 100–150 MB） | 更低（约 50–80 MB） |
| 并发模型 | 单线程事件循环；评测必须丢到队列里 **await 一个 spawn**，否则会堵住 HTTP | 协程便宜，容易不小心并行评测（2G 上是缺点） |
| 串行评测 | 和事件循环很合：同一时刻一个 `spawn`，请求照样能进 | 也能做，要自己加锁 |
| 调 g++/python | `child_process.spawn` + 超时 `kill` | `os/exec` + Context 超时 |
| Windows / Linux | 两边装 Node 即可，无交叉编译 | Windows 测、Linux 上线要 `GOOS=linux` 或在服务器 build |
| 生态 | Cookie、SQLite、JSON 与 blog 可对照抄 | 标准库强，OJ 沙箱资料多 |
| 风险 | 评测若误用同步死循环会卡住整个 API；必须超时杀子进程，且 **不要** `execSync` 无超时 | 泄漏 goroutine、并行评测打满 2G |
| 适合本项目的原因 | 单机、串行、要对齐 blog | 更适合以后独立评测机、高并发提交 |

**本期选 Node 的理由**：机器和部署已经是 blog 那一套；OJ 规模是串行评测，不吃 Go 的高并发；少一条运行时。代价是 API 进程比 Go 更「胖」、子进程管理要写仔细（超时、杀进程树、限制并发 = 1）。

**不要做的**：在 Node 里用 `vm` 跑学生 JS（本站语言是 C++/Python）；评测和 HTTP 抢同一轮死等；为了「像 Go」再拆一个 Judge 微服务。

## 5. 仓库与模块

```text
eduhub/
  docs/
  src/rd/client/        Vue SPA
  src/rd/server/        唯一 Node 服务（index.mjs 入口）
  src/rd/server/data/   仓外数据，本机与服务器同一套相对路径
    runtime/            SQLite、测例、评测临时文件（两边都有，gitignore）
    seed/gesp/          解析 JSON，约 3MB，可 rsync（gitignore）
    catalog/problems/   管理员网页改题后的正式 JSON（**进 git**，deploy 导入）
    cache/              原版 PDF / 抓取缓存（只留本机，不同步）
  src/op/               deploy.sh、nginx 片段、systemd
```

一个进程，文件按业务拆：

| 模块 | 职责 |
| --- | --- |
| auth / user | 登录、学生/教练（无家长） |
| cms | 首页三块，GET 公开 |
| problem | 题库、题单、题面 |
| submit | 提交、样例、历史、测试点 |
| judge | 内存队列 + 串行 spawn |
| contest | 练习 / OI / IOI |
| external | 官方赛历 |
| progress | 公开进度，无源码 |

路由：`/` 首页、`/problems`、`/problems/papers/:id`、`/external`、`/progress`、`/studio`。旧 `/contests` 重定向到题库。UI 见 `docs/UI设计.md`。

公开 GET：首页、进度、题列表/题面、赛历。提交和管理要登录。

## 6. 提交怎么走

```text
POST /api/submissions
  → 写入 SQLite（queued）
  → 推进程内队列（长度有限，满了返回请稍后）
  → 唯一 worker：spawn 编译 → spawn 运行测例 → 写回 SQLite
Client 每 1–2 秒 GET /api/submissions/:id 直到终态
```

OI 赛中只回 `submitted`。客观题在 Node 里对答案，不 spawn。

约束：

- 全局互斥：同时 0 或 1 个学生程序（可用队列长度 1 + `running` 标志）。
- `spawn` 必须设超时，超时杀进程树（Windows / Linux 杀法写在配置里，不要写死路径）。
- 测例：`src/rd/server/data/runtime/problems/{id}/`。
- 线上不要用 root 跑 Node。

## 7. 数据

`src/rd/server/data/runtime/eduhub.db`（gitignore）。表：users、cms_blocks、problems、statements、subtasks、testcases、problem_lists、submissions、submission_cases、contests、contest_problems、contest_registrations、external_events。

部署抄 blog：`git fetch` + `reset --hard`，**禁止 git clean**。

## 8. 部署

### 8.1 线上 Linux

工作树 `/root/deploy/eduhub`。Nginx 站点根 `/www/wwwroot/edu.jsoner.cn`（首页即该目录下的 `index.html`）。

| 脚本 | 做什么 |
| --- | --- |
| `src/op/deploy.sh` | fetch + reset，再调 client / server。**不要 git clean**（保留 SQLite / 测例） |
| `src/op/deploy-client.sh` | `vite build`，rsync 到 Nginx 目录 |
| `src/op/deploy-server.sh` | `npm ci --omit=dev`，`apply-catalog.mjs` 导入正式题面，`systemctl restart eduhub-api`，curl 健康检查 |
| `src/op/apply-catalog.mjs` | 把 `data/catalog/problems/*.json` upsert 进 SQLite 与测例目录（**覆盖**同题号） |
| `src/op/sync-gesp.sh` | 本机推 `data/seed/gesp/*.json`（约 3MB）到云主机并导入。不同步 `cache/` 里的 PDF |

本机与服务器 **目录结构相同**，不拆两套树。差别只是服务器没有 `data/cache/`（原版 PDF）。`git pull` / `deploy.sh` 只更新代码与 **catalog**。题库不要整库覆盖生产 SQLite（会冲掉线上提交）；GESP seed JSON upsert 时已发布题不被覆盖；**管理员改过的 catalog 一律覆盖**同题号。

### 8.1.1 管理员改题如何上线

1. 本机打开 `/studio`，点题目「编辑」，保存。
2. 立刻写入本机 SQLite；同时写出 `src/rd/server/data/catalog/problems/{题号}.json`（进 git）。
3. `git add` 该文件 → `commit` → `push`。
4. 服务器 `deploy.sh`：拉代码 → `apply-catalog.mjs` → 重启 API。

不要在网页里自动 push。建议只在本机改题。

systemd：`ExecStart=/usr/bin/node src/rd/server/index.mjs`，`WorkingDirectory` 仓根，`PORT=8081`，`NODE_ENV=production`。与 blog 的 `jsoner-api.service` 同形，端口错开（blog 占用 8080）。本机 Windows 开发仍默认 8080。

Nginx：单独站点 `edu.jsoner.cn`（不要写进 jsoner.cn 的 server）。`location /api/` → `127.0.0.1:8081`；SPA `try_files ... /index.html`。

本机还要有 `node`、`g++`、`python3`。不要 Go、PG、Redis。

### 8.2 Windows 本地

1. 装 Nginx、Node ≥ 22、MinGW、Python。
2. `node src/rd/server/index.mjs`（`:8080`）。
3. Nginx 反代 `/api/`，或 Vite 开发代理到 8080。

## 9. 和 PRD / 旧方案

| 需求 | 落点 |
| --- | --- |
| 网站 + 手机 | 一套 Vue |
| C/S | Nginx 静态 C + 本机 Node S |
| 2G 单机 | SQLite、串行 spawn、轮询、一个 systemd |
| 对齐 blog | Node + `node:sqlite` + 同一部署脚本形态 |

相对 Go 版删掉的：Go 工具链、交叉编译、`cmd/judge` 二进制。评测能力保留，只是管家换成 Node。
