## 1. 这是什么

公开入口页。用 **STAR**（场景 → 任务 → 行动 → 结果）讲清：为何学、学什么、怎么练、得什么；引导到大纲 / 题库 / 榜单。

### 文案原则（硬性）

首页呈现的文字必须**非常精简、大白话、不要废话**。

| 要 | 不要 |
| --- | --- |
| 短句、口语 | 公文腔、堆砌年份与部门名 |
| 一句一事 | 「一方面…另一方面…」长复合句 |
| 能删就删 | 重复强调、套话、营销词 |
| 细节丢新闻页 | 在首页复述政策全文、赛事清单 |

长度上限（CMS 写入时遵守）：

| 字段 | 上限 |
| --- | --- |
| `hero_pitch` | ≤ 40 字 |
| `star_s` 每段 | ≤ 60 字 |
| `star_t` 全文 | ≤ 120 字 |
| `star_r` 全文 | ≤ 100 字 |
| `case_studies[].body` | ≤ 50 字 |

出处、长列表、官方文件名 → `/news`，首页只留入口句。

其他原则：对照官方做法，不卖地域焦虑；纵向阅读、手机可读。

## 2. 范围

| 做 | 不做 |
| --- | --- |
| STAR 三章 + 顶区 | 城市排名、无链接的政策空话 |
| 段末链到新闻页（政策 / 公开赛） | 首页内嵌政策或公开赛长列表 |
| 教学/比赛案例 2–3 条 | 首页内嵌真实榜单/题单 |
| 匿名拉 CMS（`scope=home`） | Hero 多主 CTA 重复 |

## 4. 页面结构

```text
顶栏 → 顶区 → 一 场景·任务(S+T) → 二 路径·考期(A) → 三 行动·结果(A+R) → 页脚
```

| 区块 | STAR | CMS 字段 |
| --- | --- | --- |
| 顶区 | 摘要 | `hero_pitch`；主 CTA → `/syllabus` |
| 一 场景与任务 | S + T | `star_s`、`case_studies`、`star_t`；段末链到新闻 |
| 二 从哪练、何时练 | A | `syllabus`、`timeline` |
| 三 下一步与收获 | A + R | 静态 CTA + `star_r` + L1–L4 栈 |

章号用衬线小字「一、二、三」。`gesp_csp_bridge` 不在首页，放大纲页。

**与新闻页分工**：首页只保留叙事 + 段末入口；政策全文列表在 `/news/policy`，公开赛列表在 `/news/contests`。

## 5. 内容规格

### 5.1 顶区

| 项 | 内容 |
| --- | --- |
| 站名 / 副标 | EduHub · 信息学奥林匹克训练 |
| `hero_pitch` | 示例：`编程按官方赛道练。先定级别，再本周开练。` |
| 主 CTA | 打开大纲，选定赛道 → `/syllabus` |

### 5.2 S — 场景（`star_s`，空行分四段）

| 段 | 标签 | 要点（示例口径） |
| --- | --- | --- |
| S1 | 国家政策 | 课标已独立设科，AI 也在进课堂。出处见新闻·政策 |
| S2 | 一线在做什么 | 多按 GESP/CSP 考期练；也有黑客松等。见新闻·公开赛 |
| S3 | 未来趋势 | 更看重能考出来的成绩 |
| S4 | 我们该怎么做 | 别比城市。定级，按考期练 |

S1、S2 **不渲染链接列表**，段末分别链到：

- S1 → `/news/policy`
- S2 → `/news/contests`

### 5.3 案例（`case_studies`，S 与 T 之间）

2–3 条，含 `title`、`lens`（教学/比赛）、`body`（一句说完）。

### 5.4 T — 任务（`star_t`）

小标题：**我们的任务：对齐 GESP 等官方赛道**。

两段以内：路径 GESP→CSP→NOIP→NOI；定本周一级/本轮；用卷面和榜单对照。

### 5.5 A — 行动（章节二、三）

**章节二**：路径链路 + 赛道 blurb；`timeline` 全量不分页；脚注「日期以 CCF/GESP 官网为准」。

**章节三按钮**：

| 文案 | 目标 |
| --- | --- |
| 打开大纲，选本周级别 | `/syllabus` |
| 进题库，按卷开练 | `/problems` |
| 登录后查看训练榜单 | `/progress` |
| 了解讲师 | about.jsoner.cn |

### 5.6 R — 结果（`star_r` + L 栈）

两段以内：能写出可验证的程序；看卷面进度；奖项是信号、能力才长久；报名以 CCF 为准 → L1–L4 栈。

## 6. 数据

### CMS 字段（`cms_blocks`）

| key | 类型 | 用途 |
| --- | --- | --- |
| `hero_pitch` | 文本 | 顶区主张 |
| `star_s` | 文本 | S 四段 |
| `star_s_links` | JSON | 政策/公开赛种子（展示在新闻页） |
| `case_studies` | JSON | 教学/比赛案例 |
| `star_t` | 文本 | T 任务 |
| `star_r` | 文本 | R 结果 + 边界 |
| `syllabus` | JSON | 路径链路 |
| `timeline` | JSON | 考期年历 |

`star_s_links` 结构：`{ "policy": [...], "tier1": [...] }`。政策种子同步到 `policy_items` 表，公开赛种子同步到 `contest_items` 表，详见 `PRD-新闻.md`。

Studio（`/studio` → 首页文案）可编辑上述字段 → `PUT /api/studio/cms`。编辑时同样遵守 §1 字数上限。

**已废弃**：`benefits`、`region_contrast`（并入 STAR 字段）。

### 接口

`GET /api/cms?scope=home` 返回首页所需字段。不返回 `gesp_csp_bridge`（大纲页用）。

## 9. 验收

1. 顶区仅 1 主 CTA；`hero_pitch` 来自 CMS，≤ 40 字。
2. 章节一：S 四段（每段 ≤ 60 字）+ 段末链到新闻 + 短案例 + 短 T 段。
3. 文案无公文堆砌、无城市排名、无包奖承诺。
4. 章节二：五赛道链路可点；年历不分页。
5. 章节三：4 个 CTA + 短 `star_r` + L 栈 + 榜单侧注。
6. Studio 改 STAR 后刷新生效。
7. 未登录可读首页；受保护区门禁见 `PRD-登录门禁与模糊预览.md`。

## 10. STAR 速查

```text
S  政策（链新闻·政策）→ 一线（链新闻·公开赛）→ 趋势 → 反推句 + 短案例
T  对齐赛道；定级、定轮、定考期
A  选赛道 → 本周一级 → 按卷练 → 对照榜单
R  L1–L4 + 卷面进度 + 一句边界
```
